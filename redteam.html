Red-Team Probe Generation

GENERTIA-LLM co-evolution · SLM-guided evolution of red packets (datapath triples)
Goal, Objective & Summary
  • Goal: find where today’s immune system (AIS-IDS) is blind — generate attack ‘red packets’ that slip past current detectors while still looking realistic.
  • Objective: use a small language model (SLM-A) as the mutation operator, steered by an evolutionary loop (GRT); ground each proposal into a schema-valid, self-preserving triple; and bank the promising / uncovered ones for evaluation.
  • Summary: GRT tells SLM-A what’s uncovered; SLM-A suggests how to mutate an attack; the grounder◆ turns that into a precise triple and checks it against the guard. Whatever lands in a gap is saved to the Candidate pool and Holes repo and remembered (ExpRAG) for the next generation.

Edge guide ✕

A1
GRT→SLM-A: deterministic AIS→Vibe brief (1.2) — holes digest + self-margin hints as natural language.
the coach hands the attacker a note: where the guard isn’t looking, and how close to normal to stay.
A2
SLM-A→GND◆: the attacker proposes a mutation in language (‘push dstService toward pii-lookup, widen featureVec dim 3’).
the attacker answers in everyday words — a hunch about what to try next.
A3
GND◆→AIS: the grounder (1.3) parses the intent into a schema-valid triple and asks AIS to score it.
a translator turns the loose idea into an exact, checked attack and asks ‘would you catch this?’
A4
AIS→GRT: returns edge_gap, self_margin and whether the β false-positive budget holds.
the guard sends back a scorecard: how catchable, how normal-looking, and whether flagging it would annoy real users.
B1
GRT⇆D4 (ExpRAG): read warm-start — top-k past trajectories seed this generation.
look up what worked before instead of starting from scratch.
B2
GRT⇆D2 (RSD): read the ranked strategy/strength distribution to bias which regions to probe.
check the leaderboard of attack styles that pay off.
B3
GRT→D6: pull run parameters {β, k, τ, σ, λ}.
read the run’s settings.
C1
GRT→Candidate pool: write the evolved triple {id, srcZone, dstService, featureVec, provenance}.
save every promising attack to a shortlist.
C2
GRT→D4: append the trajectory {parent, gen, reward}.
file the whole attempt away as memory.
C3
GRT→D2: update the strategy embedding + strength.
give winning styles more attention next time.
C4
AIS→D3: log any uncovered point as a hole {triple, nearestGap, selfMargin}.
record each blind spot for defenders to patch.
C5
AIS→Telemetry: log rounds, tokens, diversity entropy.
track basic run stats: time, cost, variety.
Guard◆
if grounding is invalid, retry up to k times, then fall back to a plain GA mutation.
if the translator can’t parse the idea, fall back to a simple random tweak instead of stalling.

Key terminology ✕

Red packet / triple
⟨srcZone, dstService, featureVec∈[0,1]^d⟩ — the atomic attack sample the red team evolves.
Vibe / vibe intent
the SLM’s mutation expressed in natural language, before grounding.
Grounding (◆)
deterministic parse of a vibe intent into a validated triple (bridge 1.3); the novel step.
edge_gap
distance to the nearest AIS detector; large gap = likely blind spot.
self_margin
distance to the self-set S; kept clear so future detectors don’t flag legit traffic.
β budget
allowed false-positive rate on the self-set; breaches are penalised.
Self-set S (D1)
legitimate traffic that must never be flagged; self_margin measures distance to it.
ExpRAG (D4)
episodic memory of past trajectories; warm-starts and stores rewards.
RSD (D2)
ranked strategy/strength distribution — which regions have paid off.
Hole (D3)
an uncovered non-self point the AIS missed; target for the blue team.
Provenance
{parent, gen, guidedBy} — lineage of a triple.
Warm-start
seeding a generation with retrieved trajectories instead of random init.
GA fallback
plain genetic-algorithm mutation used when grounding keeps failing.
